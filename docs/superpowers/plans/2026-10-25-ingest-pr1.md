# Ingest freshness PR 1 (`fix/ingest-self-healing`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Production NVD, CISA KEV and EPSS data refreshes daily without a human, catches up on process start after a missed window, and CI can prove which commit production serves.

**Architecture:** Schedules become code defaults. A pure selection function in `services/ingest_catchup.py` decides which sources `_auto_ingest()` runs at startup; every run still goes through `_run_ingestion` (advisory lock, retries, run records). `/health` reports a validated 12-char commit plus scheduler state; `ci.yml` asserts the commit after deploy; a new daily workflow checks `/api/v1/ingest/health` from outside.

**Tech Stack:** FastAPI, SQLAlchemy async, APScheduler 3 (`AsyncIOScheduler`, `CronTrigger`), pytest + pytest-asyncio, GitHub Actions (bash, curl, jq).

**Spec:** `docs/superpowers/specs/2026-10-25-ingest-freshness-design.md` (section 5 "PR 1", items 1a–1f). Section 6 is decided; section 8 does not block this PR.

## Global Constraints

- Every ingestion goes through `_run_ingestion(source, trigger=...)`. Catch-up never calls an ingestor directly.
- Catch-up runs sequentially, never concurrently. Trigger label for catch-up runs: `"startup"`.
- Schedules: `INGEST_SCHEDULE_NVD = "0 1 * * *"`, `INGEST_SCHEDULE_KEV = "15 1 * * *"`; EPSS stays `"0 2 * * *"`. IC3 and economics stay unscheduled (`""`).
- New setting `INGEST_CATCHUP_ON_STARTUP: bool = True`.
- Ingest jobs `misfire_grace_time=3600`; matcher, backfill and retention stay at 300.
- `/health` adds exactly `git_commit` (12 chars or `"unknown"`), `scheduler_enabled`, `scheduled_jobs`. No hostnames, no env dump, no full SHA, no branch.
- Daily workflow hardcodes `nvd cisa_kev epss` with thresholds 25 / 25 / 49 h and ignores `healthy`.
- Every `uses:` is SHA-pinned with a version comment. Prefer plain bash + curl + jq (jq ships on `ubuntu-latest`).
- No secrets, connection strings, or hostnames beyond the public backend URL in code, logs, PR or workflow output. `BACKEND_URL` is a secret and is never echoed.
- `render.yaml`: comments only.
- Public repo. No Claude attribution in commits or the PR.
- Gate: `ruff check app tests evals`, `ruff format app tests evals --check`, `alembic upgrade head`, `alembic check`, then `pytest tests/`. Recipe: `bash <scratchpad>/gate.sh [pytest-target]` (Docker, network `ht-pr1-net`, Postgres `ht-pr1-pg`, venv volume `ht-pr1-venv`).

## Review Focus

1. **Crash loop hammering NVD.** If the process dies during a catch-up run (OOM on the 20,000-result NVD fetch, deploy SIGTERM), Render restarts it and catch-up would fire again on every boot. Expected: a source whose most recent attempt (any status, including `running`/`skipped`) started less than 1 h ago is not selected. Pinned by `test_recent_attempt_suppresses_catchup` (Task 2).
2. **`git_commit` reflecting arbitrary env content.** A malformed or non-hex `RENDER_GIT_COMMIT` must not be echoed on a public endpoint. Expected: anything not matching `^[0-9a-f]{7,40}$` (case-insensitive, stripped) reads as `"unknown"`. Pinned by `test_git_commit_rejects_non_hex` (Task 4).
3. **Superseded deploys in CI.** Two quick pushes to `main`: the older post-deploy run sees the newer commit live and goes red although nothing is wrong. Expected: older `post-deploy-healthcheck` runs are cancelled (concurrency group, cancel-in-progress). Reviewer checks by hand (Task 5).
4. **Free-plan cold start in the daily check.** The first request wakes the instance and gets a 5xx or a stale answer while catch-up runs. Expected: the workflow keeps polling every 2 min up to 30 min and only judges at the end, and fails if any of the three sources is still null or over its threshold. Reviewer walks the loop by hand (Task 6).
5. **Catch-up disabled must equal today's behaviour.** `INGEST_CATCHUP_ON_STARTUP=false` or `SCHEDULER_ENABLED=false` (local dev) must not re-ingest stale data on every restart; only empty tables seed. Pinned by `test_unscheduled_sources_only_seed` (Task 2) and `test_auto_ingest_catchup_disabled_seeds_only` (Task 3).

Selection rule (the one algorithm the tests don't fully spell out): a source is selected when `has_rows is False` (seed), or when `scheduled` and `is_stale(hours_since(last_success_at, now), thresholds[source])`. In either case it is dropped if `last_attempt_at` is within `RECENT_ATTEMPT_GUARD` of `now`. Output follows `CATCHUP_ORDER`; unknown sources are ignored.
